# ポート競合解決スキル

## 原則：指定ポートで必ず起動する

サーバーを起動するとき、**別のポートで代替起動することは絶対にしない**。

理由：フロントエンドとバックエンドはそれぞれ固定ポートで通信するよう設定されている。片方を別ポートで起動すると通信が壊れてアプリが正常に動かない。

## このプロジェクトのポート

| サーバー | ポート | 設定ファイル |
|---------|--------|-------------|
| バックエンド（Spring Boot） | 8080 | `backend/src/main/resources/application.yml` |
| フロントエンド（Vite/React） | 5173 | Viteデフォルト |
| データベース（PostgreSQL） | 5432 | 上記application.yml |

## 起動手順

### ステップ1：ポートの使用確認

```bash
lsof -ti:8080   # バックエンド
lsof -ti:5173   # フロントエンド
```

### ステップ2：競合していたら停止する

```bash
# ポートを使っているプロセスを停止
lsof -ti:8080 | xargs kill -9 2>/dev/null || true
lsof -ti:5173 | xargs kill -9 2>/dev/null || true
```

停止後、1〜2秒待ってからポートが解放されたか確認する：

```bash
lsof -ti:8080  # 何も返ってこなければOK
lsof -ti:5173
```

### ステップ3：指定ポートで起動する

競合が解消されたことを確認してから、通常通り起動する。

```bash
# バックエンド（プロジェクトルートから）
cd backend && ./mvnw spring-boot:run

# フロントエンド（プロジェクトルートから）
cd frontend && npm run dev
```

## 禁止事項

- `--port 8081` のような別ポートでの起動
- `server.port=8081` などで設定を上書きしての起動
- 競合を無視して起動しようとすること

## よくある状況

**「Address already in use」エラーが出た場合**
→ ステップ1〜2を実行してからステップ3をやり直す

**kill後もポートが解放されない場合**
→ `kill -9` で強制終了し、数秒待ってから再確認する
