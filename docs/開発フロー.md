# 開発フロー（イシュー → ブランチ → PR → マージ）

## 全体の流れ

```
① イシューを作る（「何をするか」を登録）
      ↓
② ブランチを作る（作業用の部屋を作る）
      ↓
③ ブランチで作業・コミット
      ↓
④ PR を作る（「作業終わったよ」と報告）
      ↓
⑤ main にマージ（本番に反映）
```

---

## ① イシューを作る（GitHub のサイトで操作）

1. https://github.com/toogoo1050/TASKMANEGMENT を開く
2. 上のタブから **Issues** をクリック
3. 緑の **New issue** ボタンをクリック
4. テンプレートを選ぶ（機能追加 or バグ報告）
5. タイトルと内容を書いて **Submit new issue**
6. イシューに番号（`#1` など）が付く → この番号を次で使う

---

## ② ブランチを作る（ターミナルで操作）

イシュー番号が `#5` で、タスク一覧APIを作る場合：

```bash
git switch -c feature/issue-5-add-task-api
```

確認：
```bash
git branch
# * feature/issue-5-add-task-api  ← * が今いるブランチ
#   main
```

### ブランチ名のルール

| 種類 | 形式 | 例 |
|------|------|-----|
| 機能追加 | `feature/issue-{番号}-{説明}` | `feature/issue-5-add-task-api` |
| バグ修正 | `fix/issue-{番号}-{説明}` | `fix/issue-8-fix-status-bug` |
| ドキュメント | `docs/issue-{番号}-{説明}` | `docs/issue-3-update-readme` |

---

## ③ ブランチで作業・コミット（ターミナルで操作）

普通に作業して、コミットする：

```bash
git add ファイル名
git commit -m "feat: タスク一覧APIを追加"
```

⚠️ **main には直接コミットしない！** ブランチにコミットする。

### コミットメッセージのルール

| 種類 | 意味 | 例 |
|------|------|----|
| feat | 機能追加 | `feat: タスク作成APIを追加` |
| fix | バグ修正 | `fix: ステータス更新のバグを修正` |
| docs | ドキュメント変更 | `docs: データベース設計書を更新` |
| refactor | リファクタリング | `refactor: Serviceのメソッドを整理` |
| chore | 設定・環境変更 | `chore: Dockerの設定を追加` |

---

## ④ PR を作る（ターミナルで操作）

```bash
git push origin feature/issue-5-add-task-api
gh pr create --title "#5 タスク一覧APIを追加" --body "closes #5"
```

---

## ⑤ main にマージ（GitHub のサイトで操作）

1. GitHub を開くと PR が表示されている
2. **Merge pull request** ボタンをクリック
3. **Confirm merge** をクリック
4. **Delete branch** ボタンでブランチを削除

---

## よく使うコマンド早見表

| やりたいこと | コマンド |
|-------------|---------|
| 今いるブランチを確認 | `git branch` |
| ブランチを作って移動 | `git switch -c ブランチ名` |
| 既存のブランチに移動 | `git switch ブランチ名` |
| main に戻る | `git switch main` |
| イシュー一覧を見る | `gh issue list` |
| PR 一覧を見る | `gh pr list` |
